# Architecture

## Modules

```
index.tsx   Live2DCanvas: the one entry. Maps props to a Live2D instance.
handle.ts   Live2DCanvasHandle: the public face of Live2D, one frozen object per instance.
tap.ts      The default tap reaction.
types.ts    Public and internal types.
live2d.ts   Live2D: one model on one canvas. WebGL context, sizing, pointer, render loop, model swaps.
layout.ts   place(): Layout to a model-to-clip matrix, and canvas pixels back to model units.
mouth.ts    Mouth: lip-sync level from a manual value and an audio analyser.
emitter.ts  Typed event emitter behind Live2D's events.
model.ts    Model: everything that touches the Cubism Framework. Loads and runs one model.
cubism/     The Cubism SDK for Web, generated by scripts/sync-cubism.mjs.
```

`index.tsx` imports only `live2d.ts` and what sits above it. `model.ts` and `cubism/` are behind dynamic imports.

## Loading the runtime

The Framework reads the `Live2DCubismCore` global while its modules evaluate, so the order is fixed:

1. The first `Live2D.create` imports `cubism/core.js` and sets the global.
2. Then it imports `model.ts`, which pulls in the Framework.

Both are separate chunks, about 110 kB gzipped together. The promise is shared by every canvas and reset on failure, so a later mount retries. If the page already has a Core, it is reused, with a warning when it is older than major 6.

The Framework is a global. `acquire` and `release` in `model.ts` count its users, so it starts with the first canvas and is disposed with the last, and `debug` raises the log level while any canvas asks for it.

## Lifetime of a canvas

`Live2DCanvas` splits its props across effects:

| Prop change            | Effect                                                    |
| ---------------------- | --------------------------------------------------------- |
| `pixelRatio`, `debug`  | Destroys the `Live2D` instance and creates a new one.     |
| `model`                | `live2d.load(url)`, aborted when the URL changes again or the component unmounts. |
| `layout`               | Sets `live2d.layout`, compared by JSON so an inline object does not re-run it. |
| `follow`, `idle`       | Set on the instance in place.                              |

Callbacks are read from a ref at call time, so inline functions never resubscribe.

`Live2D.load` builds the new `Model` while the old one keeps drawing, then swaps them. A newer load aborts an older one. A load that finishes as it is aborted is released, not shown. `destroy()` is safe at any time, including mid-load, which is what makes StrictMode and unmounting during a load work.

The ref becomes the handle only after the first `onLoad`, and goes back to `null` when the instance is destroyed.

## Loading a model

`Model.load` fetches the model3.json, then the moc3, physics, pose, user data, expressions and textures in parallel. Only the idle group's motions load up front, the others on first play. Textures are decoded to premultiplied `ImageBitmap`s. Any failure releases the partial model and rejects, so a load never hangs.

A model without a LipSync group gets `ParamMouthOpenY`, if it has one. Breathing and look-at use the weights from Live2D's samples.

## Each frame

`Live2D.#tick` runs on `requestAnimationFrame`:

1. Skips drawing when the canvas is off screen (`IntersectionObserver`), the context is lost, or no model is loaded.
2. Clamps the time step to 0.1 s, so a background tab does not make physics explode.
3. Updates the model: the motion (or the next idle one), then the Framework's effects (expression, eye blink, breath, look, lip sync from `Mouth.value`, physics, pose), then the parameters held by `setParameter`.
4. Draws with the matrix from `place()`, cached until the size, layout or model changes. Nothing is drawn until the shaders have compiled.

A `ResizeObserver` sets the drawing buffer to the CSS size times `pixelRatio`. A canvas with no CSS size is pinned at its current size, or it would grow every frame.

On `webglcontextlost` the loop stops drawing. On restore the Framework's per-context state is dropped and the model rebuilds its renderer and textures.

## Pointer

`follow` listens to `pointermove` on the window or the canvas and calls `lookAt`, which maps the pointer to [-1, 1] around the center of the layout frame. A tap is a `pointerdown` and `pointerup` with the same pointer, less than 10 px apart. Its hit areas come from `hitTest`, which maps the point back to model units through `place().toModel`.

## Cubism SDK

`cubism/` is written by `npm run sync-cubism -- <version>`, never by hand. The script downloads the official release and:

- Copies the Framework sources under `// @ts-nocheck`, since they are written for loose compiler settings.
- Inlines the WebGL shaders into `shaders.ts` and patches the Framework to read them from there instead of fetching them from a server folder.
- Patches in `removeGlContext`, so a destroyed canvas drops its shader set (`forget` in `model.ts`).
- Wraps the Core, a classic script, as an ES module (`core.js`) so bundlers split it into its own chunk.

Each patch must match exactly once, so an SDK update that moves the code fails loudly.

## Development

```sh
npm install
npm run dev              # playground at http://localhost:5173 with sample models
npm run build:playground # static build of the playground in playground/dist
npm run check            # types
npm test
npm run build
```

Tests run in Vitest without WebGL, so they cover the pure parts: `layout`, `emitter`, `handle`, `tap`, and the types.

Every push to `master` runs `ci.yml` and deploys the playground to GitHub Pages (`playground.yml`).

### Releasing

```sh
npm run release:patch   # or release:minor, release:major
```

On a clean tree, this checks, tests and builds, bumps the version, commits `chore: release x.y.z`, tags `vx.y.z` and pushes both. The tag runs `release.yml`, which checks the tag against `package.json`, publishes to npm with provenance, and opens a GitHub release with generated notes.

npm authenticates the workflow by [trusted publishing](https://docs.npmjs.com/trusted-publishers), so the repository holds no npm token. Trusted publishing is set on the package's npm settings, so the first version is published by hand.
